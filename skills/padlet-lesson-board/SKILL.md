# 수업자료를 패들렛 보드로

## 언제 쓰나

- 차시안을 패들렛 보드로 만들어 달라고 할 때
- 이미 있는 수업자료를 패들렛 카드로 옮길 때
- 만든 보드가 요청대로 되었는지 확인할 때

## 전제

- `PADLET_API_KEY` 환경변수에 키가 있어야 한다. 키는 보통 `pdltp_`로 시작한다
- 사용자에게 키가 없으면 패들렛의 환경설정에서 개발자 메뉴를 열어 API 키를 복사하도록 안내한다. 키 값을 대신 받아 적지 않는다
- Node 18 이상이 있어야 한다
- 키를 대화, 기록, 명령줄에 다시 노출하지 않는다. 환경변수에서만 읽는다

패들렛이 커넥터나 플러그인으로 붙어 있으면 스크립트 대신 그 도구로 같은 절차를 수행해도 된다. 어느 쪽이든 아래의 카드 기준과 검증 단계는 그대로 지킨다. 커넥터는 API를 부르는 방법만 알고, 카드를 어떻게 써야 하는지는 모른다.

## 전체 흐름

```
차시안 또는 자료
  → board.json 작성
  → scripts/create-board.mjs 실행
  → 보드 생성, 카드 보정, 검증
  → 링크 전달
```

자료를 어디서 가져오는지는 이 스킬의 관심사가 아니다. 무엇에서 왔든 `board.json`으로 적으면 된다.

---

## 1단계. 원자료 확정

- 날짜, 과목, 차시 제목을 정확히 확인한다. 사용자가 날짜를 말했으면 "가장 최근 것"으로 추정하지 말고 그 날짜로 조회한다
- 수업 목표, 활동 순서, 선택 문장, 정리, 자기점검을 뽑는다
- 한 페이지에 여러 차시가 섞여 있으면 오늘 차시의 범위만 쓴다. 아래쪽에 보존된 다른 차시의 활동을 자동으로 포함하지 않는다
- 학생 이름과 개인정보는 뽑지 않는다

## 2단계. board.json 작성

```json
{
  "보드제목": "차시 제목",
  "섹션": [
    {
      "이름": "학생이 할 행동",
      "카드": [
        { "제목": "카드 제목", "본문": "짧은 수행 안내" },
        { "제목": "고르기", "질문": "무엇을 고를까요", "투표": ["선택1", "선택2", "선택3"] },
        { "제목": "그림 카드", "이미지": "https://..." }
      ]
    }
  ]
}
```

투표 카드에는 `질문`을 함께 적는다. 없으면 제목이 카드 위와 투표 위에 두 번 나온다.

### 카드 만들기 기준

- 카드 하나에 중심 내용 하나만 둔다
- 제목에는 차시 제목만 둔다. 소개 멘트, 환영 문구, 판본 수식어를 넣지 않는다
- 섹션 이름은 학생이 할 행동으로 쓴다. `표정 풀기`, `나를 닮은 낱말`, `고른 이유`처럼 쓴다
- 학생 화면에 교사용 운영 정보를 노출하지 않는다. `배움열기`, `배움정리`, `소요시간`, `다음 시간 예고`는 넣지 않는다
- 활동을 "댓글로 적기"로 줄이지 않는다. 낱말 고르기, 분류하기, 이유 쓰기 같은 원래 수행을 실제 도구로 만든다
- 선택 활동은 투표로 만든다. 같은 과제를 댓글 카드와 투표 카드로 중복해서 늘리지 않는다
- 본문에 인터넷 주소를 그대로 노출하지 않는다
- 섹션 수와 카드 수를 미리 정해 두지 않는다. 그 차시의 실제 활동 수에 맞춘다

### 특수교육 수업일 때

- 문장은 짧고 선택지는 분명해야 한다
- 장면 설명 → 가능한 해석 → 고를 말이나 행동 순서로 구성한다
- 눈맞춤 같은 단일 행동을 정답으로 강요하지 않는다. 몸의 방향, 고개 끄덕임, 핵심 낱말, 선택카드 같은 대체 표현을 함께 허용한다
- 학생의 개인 경험을 공개하도록 요구하지 않는다. 인물과 장면 중심으로 참여하게 한다
- 자기점검은 실제로 고를 수 있는 형태로 둔다

## 3단계. 보드 만들기

```bash
node scripts/create-board.mjs board.json
```

스크립트가 하는 일은 다음과 같다.

1. `POST /v1/ai-recipe-boards`로 보드를 만든다
2. `statusUrl`을 3초 간격으로 조회한다. `in_progress`에서 `success`가 될 때까지 기다리며 최대 2분이다
3. 만들어진 보드를 다시 읽는다
4. `board.json`에 있는데 보드에 없는 카드를 `POST /v1/boards/{id}/posts`로 채운다
5. 섹션 수, 카드 수, 제목, 본문, 링크를 확인해 보고한다

빈 보드를 직접 만드는 `POST /v1/boards`는 개인 키로 거부된다. AI Recipe가 유일한 입구다.

## 4단계. 검증

생성 성공만으로 끝내지 않는다. 반드시 다시 읽어 확인한다.

- 제목이 요청과 같은가
- 섹션과 카드 수가 의도한 구조와 맞는가
- 각 카드의 제목과 본문이 비어 있지 않은가
- 카드가 올바른 섹션에 붙어 있는가
- 일반 링크와 슬라이드 링크가 실제로 열리는가
- 투표를 넣었다면 다시 조회했을 때 `attachment.poll`이 있는가

AI Recipe 결과는 지시문과 다를 수 있다. 다르면 3단계의 보정으로 맞춘다.

## 5단계. 전달

- 보드 제목
- 섹션 수와 카드 수
- 보드 링크
- 슬라이드 링크
- 학생 접속용 QR 주소
- 검증 완료 여부

## 그림이 없을 때

그림이 없어도 보드는 만들어진다. 먼저 글자 카드로 진행하고, 그림이 꼭 필요한 활동에서만 다음을 따른다.

1. 원자료에 쓸 그림이 있는지 먼저 본다. 있으면 그것을 쓴다
2. 없으면 사용자에게 어떻게 할지 묻는다. 그림 만드는 도구를 쓸지 말지는 사용자가 정한다
3. 도구 연결이 필요하면 무엇이 필요한지 알리고 동의를 받는다. 연결을 대신 결정하지 않는다
4. 동의를 받았으면 로그인 창을 띄우는 데까지만 한다. 로그인은 사용자가 직접 한다. 비밀번호나 인증 값을 대신 입력하거나 받아 적지 않는다
5. 사용자가 원하지 않으면 글자 카드로 진행하고 다시 권하지 않는다

정확성이 중요한 자료는 만들어 낸 그림에 의존하지 않는다. 입모양이나 조음기관 그림이 그렇다.

도구별 연결 절차는 [references/sources.md](references/sources.md)에 있다. 모두 선택 사항이며, 하나도 없어도 이 스킬은 그대로 동작한다.

## 하지 말아야 할 판단

- 작성창이 열리는 것과 실제 게시가 되는 것은 다르다
- 링크를 눌러 이동하는 것과 자동 연동은 다르다
- API 등록이 성공한 것과 그림이 실제로 보이는 것은 다르다
- 그림 파일이 생긴 것과 내용이 맞는 것은 다르다
- 확인하지 못한 부분을 완료로 묶어 보고하지 않는다
- **보드 화면은 늦게 그려진다.** 연 직후 화면에는 구역만 보이고 카드가 비어 보인다. 화면을 보고 실패로 판단하지 말고 API로 다시 읽어 확인한다

## 알려진 함정

| 증상 | 원인 | 해결 |
|---|---|---|
| `You must use a zapier integration` | `POST /boards` 사용 | `POST /ai-recipe-boards`를 쓴다 |
| 카드가 비어서 생성됨 | `attributes.subject`에 넣음 | `attributes.content.subject`에 넣는다 |
| 파이썬에서 응답 없음 | 클라우드플레어가 기본 urllib를 막음 | Node의 `fetch`를 쓴다. 재시도하지 않는다 |
| 투표가 안 만들어짐 | 형식 오류 | `content.attachment.poll`에 `{"question":"...","choices":["...","..."]}`, 선택지는 2~4개 |

지원이 확인되지 않은 엔드포인트를 추측해서 부르지 않는다. 문서 색인은 `https://docs.padlet.dev/llms.txt`에 있고 문서 주소 끝에 `.md`를 붙이면 스키마를 읽을 수 있다.
